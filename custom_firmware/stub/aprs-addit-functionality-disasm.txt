Стоковая функция бипа: 0x01E5241A(id)

Отправка beacon (для кнопки): 0x01E5C3D4

- Вызов без аргументов шлёт стоковый beacon ровно как таймер.
- Внутри проверяет: 
	b[0xC0F0+218] (APRS/TX вкл) = 1, 
	b[0x72400+2688] (готовность) ≠ 0, 
	координаты [0x72400+2704]/[2708] ≠ 0/0, 
	тип кадра b[0xC0F0+1091] ≤ 4 — дальше tbh/tbb выбирает Mic-E/позицию.
- Ветка «только по PTT-линку» — обёртка 0x01E5C4E4 (если b[0xC0F0+1058] ≠ 1 → выходит). 
	
Для кнопки вызывать 0x01E5C3D4 напрямую — он не смотрит на PTT-link.

Beacon-таймер (чтобы понять, что не трогаем): 0x01E82FB2

- b[0xC0F0+1059] = timed beacon, h[0xC0F0+1060] = интервал (сек), счётчик [0x72400+540], порог interval*100, по истечении — call 0x01E5C3D4.
- Хук на кнопку не конфликтует: таймер и ручной вызов идут в одну функцию.

APRS POPUP (для beep-beep): показ = 0x01E85782, точка вызова = 0x01E86424

- Попап рисует окно 160×128, строки на y=25/45/65.
- Вызывается из обработчика кадра 0x01E86238, 
	где b[0x72400+8588] = флаг разрешения (0 → не показывать), 
	проверяются канал [0x72400+444/464/472] и b[0xC0F0+1090] (RX-канал).
- Значит бип ставить непосредственно перед call 0x01E86424 (или в начале 0x01E85782) — сработает только при реальном показе попапа, после всех проверок, включая разглушку.

Плюс сопутствующее: Settings VM база 0x9424, аксессор по ID 0x01E50128, ID банка APRS 12412…12564 (timed beacon = 12527, interval = 12528, PTT-link = 12526).

Непроверенное/риски: 
- адреса получены статическим анализом app.bin и не проверены на железе; 
- 0x01E5C3D4 рассчитан на вызов из контекста APRS-задачи — при вызове из чужого потока/прерывания возможны гонки по общей структуре [0x72400+560]; 
- формат вызова call 0x01E5C3D4 из патча нужно собрать в pi32v2 и проверить, что регистры (особенно SP) в порядке; бип зависит от доступности tone-движка snd.c в точке попапа.
