# Пакет картинок TD-H9 по Bluetooth (DKXCEPIC)

`td9_kpi.py` загружает **набор картинок** на resource flash рации TD-H9
по Bluetooth. Картинки хранятся в свободной области — «хвосте» font-партиции
(`0x717000..0x7FFFFF`), которую стоковая прошивка не использует.

Смотреть картинки на рации будет приложение **DKXCEPIC** (меню Back →
DKXCEPIC; Up/Down листает картинки по циклу, Back — выход).

## Формат области

Заголовок + картинки (сырой RGB565 big-endian):

```
0x717000  "DKXCEPI"    7 байт magic
0x717007  count         1 байт, число картинок далее
0x717008  картинка 0    160×128 RGB565 big-endian (40 960 Б)
          картинка 1    ...
          ...
```

## Команды

Все через `poetry run`.

### Проверить, что область свободна
```
poetry run python td9_kpi.py check [--addr 0x717000] [--span 0x1000]
```
- По умолчанию читает 4 КиБ с `0x717000`.
- Если там уже лежит DKXCEPIC-пакет — распознаёт его (кол-во картинок,
  размер, сколько свободно после) и предлагает `write`/`forcewrite`/`erase`.

### Записать картинки
```
poetry run python td9_kpi.py write a.png b.jpg c.bin [--addr 0x717000]
```
- `png/jpg` — Pillow: ресайз до 160×128 → RGB565; `.bin` — готовый raw.
- Сначала читает область:
  - если уже записано **идентично** — пропускает («Already written identically»);
  - если область **занята** другим — стирает занятые сектора и пишет;
  - если **свободна** — сразу пишет.
- В конце верифицирует запись (высокоскоростное bulk-чтение).

### Принудительно записать (стереть и записать)
```
poetry run python td9_kpi.py forcewrite a.png b.png [--addr ...]
```
- **Всегда стирает** занимаемые сектора перед записью, не полагаясь на
  проверку содержимого.

### Стереть записанные картинки
```
poetry run python td9_kpi.py erase [--addr 0x717000]
```
- Если на `--addr` лежит DKXCEPIC-пакет — читает count, вычисляет точный
  размер и стирает ровно сектора пакета.
- Если заголовка нет — стирает `--span` (по умолчанию 4 КиБ).
- После стирания сектора соответствуют 0xFF — область снова свободна.

### Выгрузить байты области
```
poetry run python td9_kpi.py dump --addr 0x717000 --span 0x1000 --out файл.bin
```

## Параметры

| Аргумент | По умолчанию | Назначение |
|---|---|---|
| `--addr` | `0x717000` | стартовый адрес области |
| `--span` | `0x1000` | размер для `check`/`dump` (4 КиБ) |
| `--out` | `kpi-dump.bin` | выходной файл для `dump` |

## Скорость и протокол

- Запись идёт через S2 write service по 32-байтным блокам
  (erase → program → verify), как в `td9_logo.py`.
- **Чтение (check / verification / dump)** использует **bulk-read (S1 fast)**:
  рация стримит данные пачками по ~240 Б за запрос вместо 32 Б, поэтому
  проверка/верификация в разы быстрее (примерно 3–4 КиБ/с вместо долгих
  32-байтных циклов).

## Ошибки правописания (важно)

- Если после `write` видите `read timeout` на `Verifying` — это старая
  проблема чтения по 32 Б; перезапустите (теперь verify идёт bulk-ом).
- `erase`/`write` перед стиранием передают **актуальный CRC сектора** в
  erase-команду и проверяют результат; если рация отклонит — появится
  сообщение с причиной (напр. «sector CRC mismatch»), а не ложный успех.
